## 0. 产品定位

cosine 分阶段演进，不追求一次做全：

1. **近期（MVP）**：通用 2D GUI 框架。自研 retained-mode UI，Vulkan 渲染，Linux Wayland + Windows 双平台。
2. **中期**：脚本驱动的程序化动画引擎。XEL 首版内嵌，最终成为主要创作语言。
3. **中期**：时间轴关键帧动画编辑器，与脚本共用同一套场景/时间轴内核。
4. **中期**：2D 动画导出（离屏渲染、帧序列、视频编码）。
5. **长期**：2.5D / 3D 变换、完整创作工具链。

当前渲染只实现 2D。先完成 2D GUI → 2D 动画内核 → XEL 绑定 → 2D 编辑器与导出，再进入 2.5D/3D；数据结构和接口不得写死 2D 假设。

### 首版非目标

- 3D 网格、光照、阴影、物理
- 音频、视频解码
- 插件系统、多人协作
- 完整 IDE、语言服务器、调试器
- 即时模式 GUI（immediate mode）；本项目明确采用 retained-mode

## 1. 已完成基线

### 1.1 XEL 解释器

提交区间：`31a1a1a` → `3b72f8c`，以及 `91b7f96`。

- 词法：`token` / `lexer`，支持标识符、数字、字符串、运算符。
- 语法：递归下降 `parser`，生成 AST；`ast/expr`、`ast/stmt` 分离。
- 求值：`evaluator` + `environment`，支持四则运算、比较、变量、作用域。
- 控制流：分支、循环；修复过循环条件永真、`env.get()` 递归等问题。
- 函数：声明、调用、返回值、native 函数。
- 工具：`xel-vs-extension` VS Code 语法扩展。
- 测试：`test_interpreter_token`、`test_intepreter_tree_structure`、`test_intepreter_tree_evaluator`。

### 1.2 Vulkan 后端

提交区间：`34963ad` → `dc69539`，以及后续修复。

- 实例、物理设备、逻辑设备、队列、Surface。
- SwapChain 创建、重建、动态视口、呈现模式选择。
- 命令池、命令缓冲区、单次命令。
- 图形管线、顶点/片元着色器、slang 编译接入。
- Push constant、2D 变换（scale / translate）。
- Staging buffer、device-local 顶点/索引缓冲、动态顶点缓冲。
- Uniform buffer、描述符集/描述符池、组合图像采样器。
- 纹理加载、采样、透明窗口。
- 批量绘制、索引绘制、scissor 裁剪。

## 5. 验证与质量门

### 本地命令

```bash
cmake -S . -B build
cmake --build build -j
ctest --test-dir build --output-on-failure
```

### 测试分层

- 纯逻辑测试（不依赖 Vulkan/窗口）：布局、命中测试、事件冒泡、文本测量、时间轴求值。
- 解释器测试：沿用现有 3 个测试，XEL 绑定后增加宿主 API 测试。
- 渲染冒烟：lavapipe 或真实 GPU，跑 `ui_demo` 若干帧，检查 validation。
- Windows：MSVC 构建 + 最小运行冒烟（M3 起）。

### 质量门

- `-Wall -Wextra -Wshadow` 无新增警告。
- Linux CI 增加 ASAN 与 lavapipe 冒烟；Windows MSVC 构建实测。
- Debug 构建 + `VK_LAYER_KHRONOS_validation` 无错误。
- 资源缺失、shader 编译失败、初始化失败均有明确错误信息。
- 每个阶段出口必须可运行、可验证；不允许“只写了代码但跑不起来”的交付。

### 性能

M1–M3 只做 instrumentation（frame time、draw call、顶点数），不设硬指标；M6 之后根据真实项目再定预算。

## 6. 依赖策略

- 保持最小依赖集；新增依赖前必须追加决策。
- 现有：Vulkan SDK（vulkan-hpp、validation layers）、GLFW、GLM、STB、FreeType、Slang（shader；glslc 作为简单 shader 的回退）。
- STB 固定 commit；GLM 由 CMake 显式声明；不再依赖开发机隐式安装。
- 暂不引入 VMA；当动态资源数量与碎片成为实际问题时再决策。
- 视频导出优先外部进程管道（ffmpeg），避免直接把编解码库耦合进核心。
- 测试优先使用 CTest + 简单断言，不急于引入测试框架。

## 7. 风险与未决问题

### 风险

- **平台**：GLFW 已改为 Wayland/X11 option，但 Windows 与 X11 仍未实测。
- **shader 工具链**：slangc 在 Windows/CI 上安装不便；需要准备 glslc 回退或预编译 spv。
- **Windows**：Vulkan SDK、GLFW、字体/资源路径与 Linux 差异需要在 M2–M3 持续验证。
- **文本**：UTF-8 / CJK / 字体图集质量可能成为 GUI MVP 的瓶颈。
- **2.5D/3D**：如果 M1/M2 把 2D 假设写死，M7 会返工；现在就要避免固定 `vec2` 变换接口。
- **视频导出**：编码器选型、帧同步、色彩空间都需要在 M6 单独决策。
- **范围蔓延**：GUI 控件数量容易失控；MVP 只做已定的基础控件列表。
- **全局状态与 demo 债务**：`active_font_atlas()`、全局 `theme()`、`ex4` 手动 UI、Renderer 演示逻辑都会阻碍多窗口与测试，需在 M2-F/M3 清理。
- **文档时效**：`code_review` 基线较早；当前评估见 `docs/project_assessment.md`，后续修复需同步标记。

### 未决问题

1. “视频导出”确认为“把动画渲染结果导出为 mp4/gif”，而不是“播放/解码外部视频”？当前按前者规划。
2. 3D 是“完整 3D 场景”还是“2.5D 层级变换 + 透视相机”？当前按后者规划，完整 3D 留到更后面。
3. Windows 最低版本与目标 GPU/驱动范围。
4. 字体图集是提交进仓库，还是构建时生成？
5. 项目文件格式：JSON、二进制还是自定义文本？
6. XEL 的类型系统边界（动态类型是否足够，是否需要结构体/数组/模块）。
7. CI 托管平台（GitHub Actions / 自建）与是否允许联网拉依赖。

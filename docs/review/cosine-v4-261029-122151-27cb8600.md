## 2. 重复实现

### 2.1 自绘列表四套并存（最大冗余源）

`Table`(451)、`TreeView`(594)、`FileBrowser`(338)、`TimelineView`(554) 各自维护：行高、滚动偏移、选中索引、键盘上下移动、`ScrollMode`、`clamp_scroll`。

今天把 `FileBrowser` 改成委托 `Table`，代码只从 371 降到 338 —— 因为 `FileBrowser` 里混着两件事：文件系统语义（目录优先排序、`..`、扩展名过滤、双击进目录）和列表渲染（行、滚动、选中）。

**建议抽 `ListView`**：行渲染 + 滚动 + 选中 + 键盘。
- `Table` = `ListView` + 多列
- `TreeView` = `ListView` + 缩进/展开
- `FileBrowser` = `ListView` + fs 语义
预估减少 500–600 行。

### 2.2 滚动实现三套

`ScrollView`/`ScrollPanel`、`Table::scroll_`、`TextInput` 内部滚动。三者都支持 `ScrollMode`（Smooth/Line/Fast），但 `clamp_scroll`、目标值逼近、平滑系数各写一遍。

**建议抽 `ScrollState`**（值 / 目标 / 速度 / 模式 / clamp），四处复用。

### 2.3 文字垂直居中（同一个 bug 已踩三次）

本次会话中，`Window` 标题、`FileBrowser` 条目、`Table` 单元格先后因「拿字号当行高」导致文字偏下。已抽出 `FontAtlas::centered_text_y()`，但 `drag_float`、`color_input`、`menu_bar`、`slider` 仍是各自手算 `atlas->line_height()`。

**建议**：全部改走 `centered_text_y`，并在测试里加一条约束（例如「自绘文字处不得出现 `- t.*text_size * 0.5f`」）。

### 2.4 折叠逻辑两套

`Window` 的标题栏三角与 `Section` 的分组三角各写一份绘制 + 命中判断。

**建议抽 `CollapsibleHeader`**（标题 + 三角 + 点击切换），两处复用。

### 2.5 浮层概念三套

- `Dialog`：作为 `overlay` 添加，遮罩内联在 `append_to` 里
- `Window`：挂在 `children_`，模态时由 `UIRoot` 造一个 `Scrim` 压 z
- `Tooltip` / `Dropdown`：各自走 `overlays()`

`UIRoot::layout_child` 里已经出现 `dynamic_cast<Scrim*>` 特判 —— 说明「浮层」没有显式概念，只能靠类型判断补救。

**建议**：显式 `Layer` 概念（content / floating / modal），`layout` 按层处理，去掉 `dynamic_cast`。

## 3. 隐式约定造成的高风险点

### 3.1 `parent` 必须手动设置

`Widget` 没有统一的 children 存储，各容器自己声明 `std::vector<std::unique_ptr<Widget>>`。`Vbox::add()` 会 `set_parent(this)`，但 `Window` 构造里直接 `children_.push_back(...)` 就漏了 —— 本次会话中这直接导致「内容区点不动、拖不了窗口」，而标题栏拖动正常（命中的是 `Window` 自己，不走冒泡）。

**建议**：`Widget::adopt(std::unique_ptr<Widget>)` 作为唯一入口（`set_parent` + `set_context` + 存入 `children_`），禁止直接 `push_back`。

### 3.2 `measure()` 存在三种语义

| 实现 | 行为 |
|---|---|
| `Vbox` | 递归测量 + `measure_valid_` 缓存 |
| `Table` / `FileBrowser` / `TimelineView` | 忽略 `constraints`，返回 `clamp_size(min_size())` |
| `Label` | 带 key 的测量缓存（key 含图集指针） |

而 `invalidate_measure()` **不向上传播** —— 本次会话中 `Section` 切换 Tab 后内容不刷新，要靠拖动窗口才更新，根因就在这里（`Section::measure` 拿到的是 `content_` 的旧缓存高度）。

**建议**：文档化 `measure` 契约（`constraints` 必须被尊重，或显式标记为 fixed），并让缓存失效沿 parent 链传播。

### 3.3 `hit_testable` / `focusable` / `clips_children` 三布尔

行为组合没有文档化矩阵。例如 `Vbox::hit_testable() = false`（为了让点击冒泡到父级拖动），而 `Panel` 是 `true`（为了裁剪子项）—— 差异不直观，容易误设。

### 3.4 事件派发链没有测试

本次两个 bug（`local_.pos` 被 `UIRoot::layout_child` 每帧覆盖、`body_` 缺 `parent`）**只有真实派发路径才暴露**：`test_ui_window` 直接调 `on_mouse_down` / `on_mouse_move`，绕过了 `hit_path` + 冒泡 + layout。

**建议：加 `test_ui_dispatch`**，用 `UISystem` 派发合成事件（`down → move → up`），断言窗口被拖动、内容区点击能冒泡到窗口。这是目前测试体系里最大的盲区。

## 4. `Widget` 职责过重

406 行基类同时承担：布局槽位、measure 缓存、事件虚函数组、焦点、z-index、absolute 定位、主题版本、clip 栈、padding/margin、min/max size、size_percent、aspect_ratio。

后果是派生类倾向「什么都塞」：`menu_bar 857` 行、`window 557` 行。

短期不建议拆（动全局基类，回归面太大），但新增能力时应优先考虑「独立组件 + 组合」而不是往 `Widget` 或 `Window` 里加。

## 5. 渲染层缺口

| 项 | 现状 |
|---|---|
| 圆角抗锯齿 | 硬边（D01），`append_rounded_rect` 是分段线段 |
| 外阴影 | 无，窗口层次靠 1px 边框 + `elevated` 令牌区分 |
| 整组透明度 | 本次补了 `DrawList::push_opacity`（顶点色乘子）。它是**整体线性乘**，不支持「组内先混合、再整体半透明」（需要离屏合成） |
| 顶点写入分散 | 全项目 39 处 `vertices.push_back` 绕过 `DrawBatch::add_vertex`。本次已收拢 6 个核心文件，仍剩 `timeline_view`(4) / `scene_view`(4) / `renderer.cpp` 调试绘制(16)。这类支路会让新加的顶点属性被漏掉 |

## 6. 主题令牌与 StyleRole 并存

`Theme` 有 30+ 颜色字段，同时又存在 `StyleRole` + `ControlState` 映射。控件里两者混用：一部分读 `t.button_bg`，一部分读 `t.style(StyleRole::Surface, state)`。

本次新增 `elevated` / `elevated_border` 走的是「加字段」路线，会让「哪个令牌控制哪个控件」变得不可追踪。

**建议**：先补一份「令牌 → 控件」对照表，再决定是否把纯色字段收编进 `StyleRole`。

## 1. 现有链路

```
UIRoot::layout()
 └─ layout_child(child)
      ├─ child.fills_parent()  → 直接 arrange(root 整块)              （Scrim）
      └─ 否则 child.measure(root.size) → clamp_size → arrange({root.pos + child.x(), size})
                              ↑ 不经 measure_child，也不扣 margin；自由画布用 child.x()/y()

容器一轮（Vbox 为例）
 measure(constraints)                              arrange(slot)
   子项：measure_child(cs)  ────────────────▶       子项：measure_child(同款约束) ← 再测一次
   累加 natural_h，flex 分配                      ▶  按 flex 分 extra（extra<0 不收缩，直接溢出）
   → clamp_size → cached_measure_                 → global_ = slot（local_ 不写，见 P0-1）

measure_child（Widget，唯一规格入口的候选）
   pct(按 constraints 计价) → child.measure → aspect_ratio → clamp(min/max)
   ※ 主轴 margin 不参与；arrange 的 stretch 完全绕过本函数（见 P0-2 / P1-7）

旁路（不经过 measure_child 的"隐式 fill"）
   UIRoot::layout_child · TabView::measure/arrange · ScrollPanel::measure · DialogHost::measure
   Splitter::arrange（连 measure 都不做）；Section/CollapsibleHeader 用 width = constraints.x 模拟填满

裸容器（Vbox/Hbox/Grid/Wrap）不接主题：set_default_padding(4) + spacing_=4，无 set_context 覆写
```

## 3. 实测问题

全部结论由探针实测或 `grep` 证实（`/tmp/layout_probe.cpp`、`/tmp/layout_probe2.cpp`，
链接 `build/src/libcosine_ui.a`）。`[n]` 是探针输出编号，完整输出见 §8。

### P0-1 容器 `arrange()` 不写 `local_`：`local_bounds()` / `x()/y()/width()/height()` / `layout()` 全部失真

`Vbox::arrange()` 只写 `global_ = slot`（vbox.cpp:99），从不 `set_pos/set_size`
（hbox.cpp:92、grid.cpp:217、wrap.cpp:140 同）：

```
[8] after arrange(400x300): box.local=100x100@0,0 child.w=400.0    ← local 还是构造尺寸
[8] after box.layout():      box.local=100x100@0,0 child.w=100.0    ← layout() 用陈旧矩形重排
```

机制：`set_pos()`/`set_size()` 内部会 `mark_layout_dirty()`（widget.hpp:54-57），在 `arrange()`
里调用就会把整棵树重新弄脏，于是容器作者选择"不写 local_"。代价：

| 消费者 | 后果 |
|---|---|
| `Widget::local_bounds()`（公开 API） | 容器永远返回构造期矩形；`DebugWindow` 的 Pos/Size 对容器显示 0,0 / 0×0 |
| `Vbox/Hbox/Grid/Wrap::layout()`（`arrange(local_bounds())`，vbox.cpp:32 等 4 处） | 用陈旧矩形重排——探针 [8] 把被拉伸的子项从 400 打回 100。目前只有 `UIRoot::layout()` 被调用，属**潜伏 bug** |
| `x()/y()/width()/height()` | 对容器无意义；"读父容器尺寸"的写法一律拿到 0 |
| `UIRoot::layout_child()` | 用 `child.x()/y()` 定位，只对显式 `set_pos` 过的 root 子项（`Window`）成立 |

根因是**"布局写入"与"脏标记"耦合**：缺少"只改几何、不失效"的入口。建议新增
`Widget::set_geometry(Rect)`（或 `apply_slot()`）供 `arrange` 使用，让 39 个 `arrange` 统一写
`local_ = slot`（`Window`/`Splitter`/`Table` 这类固定尺寸控件可显式例外，但要写注释）。

### P0-2 `size_percent` 无预算，且主轴 `margin` 不参与计价

`measure_child()` 的百分比是"**按父给的 constraints 逐个子项各自计价**"：两个 `pct_y = 1`
的子项各自拿到整高，三个 `pct_x = 0.5` 各自拿到半宽：

```
[4] vbox(pct_y=1 x2).measure = 10.0 x 600.0 (inner_h=300)
    a h=300.0 at y=0.0 ; b h=300.0 at y=300.0 (bottom=600.0)       ← 溢出容器 300px
[5] hbox(0.5 x3).measure.x = 600.0 ; arranged x = 200.0/200.0/200.0 ← 溢出 200px
```

同一份 `size_percent` 在四个容器里行为不同，且**只有交叉轴的 margin 被扣减**：

| 容器 | 子项拿到的 constraints | `pct_y` | `pct_x` | margin 扣减 |
|---|---|---|---|---|
| `Vbox` | `{inner_w - ml - mr, inner_h}` | 按容器内高 | 按容器内宽 | 只扣交叉轴（x） |
| `Hbox` | `{inner_w, inner_h - mt - mb}` | 同上 | 同上 | 只扣交叉轴（y） |
| `Grid` | `{cell_w, inner_h}`（cell_w 已扣 ml/mr） | 按容器内高 | 按单元格宽 | 只扣交叉轴 |
| `Wrap` | `{inner_w - ml - mr, 1e8}` | **永不生效**（y 无界） | 按容器内宽 | 只扣交叉轴 |

后果：主轴 `margin` 不进 pct 计算、却在 arrange 里被加回去 → "pct + margin" 必然溢出；
`pct` 与 `flex_grow` 组合也无定义（`Vbox::measure` 对 flex 子项只取 `min_size().y`，
`arrange` 的 extra 分配不看 pct，vbox.cpp:83-85/143-163）。
测试只覆盖"单子项百分比"（`test_ui_percent_aspect` 10 例），无"多子项预算"用例。

建议：主轴引入预算（先解析全部 pct/flex，再分配剩余，总和 ≤ 可用），margin 全轴参与；
或明确写成"百分比 = 容器尺寸固定比例、不做贪心约束"并禁止同轴多个 pct 子项。

### P0-3 `measure()` 的宽度语义：**1 处真违约** + **4 处"隐式 fill"**（第 1 版只记了三处，且分类不准）

```
[3] wrap.measure({200,100}) = 300.0 x 20.0  (<=200 ? NO)   ← 唯一真违约
```

| 位置 | 行为 | 分类 |
|---|---|---|
| `Wrap::measure`（wrap.cpp:130） | `total_w = max(constraints.x, content_w)`，注释自辩"保证折行结果与 measure 一致" | **违约**（返回 > 约束）→ 父按 300 摆放溢出；放进 `ScrollView(Axis::Vertical)` 平白多出横向滚动条 |
| `Section::measure`（section.hpp:72） | `float width = constraints.x;` | 隐式 fill（吃满可用宽）→ 两个 Section 并排各自报全宽 |
| `CollapsibleHeader::measure`（collapsible_header.hpp:48） | `float width = constraints.x; if (width < 0) width = local_.size.x;` | 隐式 fill（同上，第 1 版遗漏） |
| `ScrollView::measure`（scroll_view.cpp:153） | 直接 `return constraints` | 隐式 fill；约束无界（1e8）时返回 **1e8**，进 Wrap/Grid 的"自然宽"分支会爆炸（只被 max_size 挡住） |
| `DialogHost::measure`（dialog.hpp:174） | 直接 `return constraints` | 隐式 fill（模态宿主），再靠 `arrange` 里的 `margin=24` 手工内缩（第 1 版遗漏） |

前 4 个（Section/CollapsibleHeader/ScrollView/DialogHost）不"违约"，它们的代价是：**兄弟之间互相争抢**（各自报全宽）与**无界约束下 1e8 爆炸**。
两类问题（违约 + 隐式 fill）的共性是**缺一个 `Fill` 尺寸模式**（`flex_grow` 的横轴/整块版本）。
升级为 P0 的理由：它直接污染父级的测量结果，而 `Fill` 模式是升级清单第 2/8 条的前提。

### P1-4 `measure` 缓存靠**副作用**失效，且跨布局**从不命中**

缓存没有版本键；`UIRoot::set_theme()`（root.cpp:99-106）只 `set_context()` + `mark_layout_dirty()`，
而 `mark_layout_dirty()` 只清**自身**缓存并向上冒泡（widget.hpp:330-335），`UIRoot` 也没有覆写
`invalidate_measure()` —— `Editor::apply_settings()` 里的 `root_->invalidate_measure()`
（editor.cpp:870）其实只清了 root。

它能"看起来正确"，是因为 `arrange()` 期间叶子的 `set_size()` 会把脏标记冒泡到所有祖先：

```
[7b] before: outer.measure=30.0 button.h=30.0
[7b] right after set_theme: outer.measure=30.0            ← 主题已换，缓存仍是旧值
[7b] after layout: outer.measure=60.0 button.h=60.0 outer.global.h=30.0
                                                          ← 单遍布局：容器 30 高、内容 60 高
[7c] tick#1: outer.h=30.0 → tick#2: outer.h=60.0           ← 走 UISystem 时下一 tick 自愈
```

更严重的是**缓存反过来也没收益**（附录 B）：

```
after first layout: 2
after re-measure (same constraints): 3   ← 期望命中不变，实际又走了一遍
```

即"每次布局结束，子项 `set_size` 已经把祖先缓存清空" → 那 5 份缓存三元组当前只贡献复杂度，
同时又留下"子树里没有叶子 set_size（Splitter / Window / 纯容器）时读到旧尺寸"的风险
（`TabView::measure` 还会测不可见页，它们的 arrange 从不运行，缓存永远不被副作用清掉）。

建议：要么删掉这套缓存，要么加 `theme_revision()` 版本键 + 每轮 layout 末尾统一清；
并让 `set_theme()` 递归失效。

### P1-5 每个子项每轮布局被测量 2 次（文本类控件即 2 次全量字形遍历）

```
[1] after vbox.measure:  a=1 b=1
[1] after vbox.arrange:  a=2 b=2
[2] after root.layout:   a=2 b=2
```

`Vbox/Hbox/Grid/Wrap::arrange` 为了 flex/对齐会再调一次 `measure_child`，而
`FontAtlas::measure()`（font_atlas.cpp:274-294）**没有缓存**：逐码点 `ensure_glyph` + 累加 advance。
于是 `Button` / `TabBar` / `Dropdown` / `MenuItem` 的文本每轮布局被量 2 遍；`Label` 有单槽缓存兜底，
其余没有。`Grid::arrange` 先测列再测行（自身 2 次），`TabView::measure` 还会测所有页面
（tab_view.hpp:140-144）。

建议：`arrange` 复用 measure 结果，或给 `FontAtlas::measure` 加字符级 memo。

### P1-6 叶子控件把 **arranged 尺寸**当自然尺寸：拉伸后不可回缩（第 1 版遗漏）

```cpp
// 典型（color_rect.hpp:37）
glm::vec2 measure(glm::vec2) override { return local_bounds().size; }
```

| 控件 | 位置 | 读的是什么 |
|---|---|---|
| `ColorRect` | color_rect.hpp:37 | `local_bounds().size` |
| `Image` | image.hpp:125 | `clamp_size(local_bounds().size)` |
| `ListView` | list_view.hpp:68 | `clamp_size(local_.size)` |
| `SceneView` | scene_view.hpp:40 | `clamp_size(local_bounds().size)` |
| `TimelineView` | timeline_view.hpp:77 | `clamp_size(local_bounds().size)` |
| `TreeView` | tree_view.hpp:179 | `global_.size.x > 0 ? global_.size : local_.size` |
| `CollapsibleHeader` | collapsible_header.hpp:49-50 | `{width, height()}` |
| `Dropdown` 列表 | dropdown.hpp:34 | `local_.size` |
| `MenuBar` 弹出列表 | menu_bar.hpp:124 | `local_.size` |

后果与 `flex_grow`/stretch 直接冲突：一次拉伸会把 `local_.size` 写成放大值，下一次 `measure`
就把它当成自然尺寸 → **只能变大不能变小**（窗口缩小时不回收）。
`Spacer` 的注释（spacer.hpp:18-21）正是为了绕开这一点而返回 `preferred_`；
`Table` 也明确写了"不读 global_，避免依赖 arrange 顺序"（table.hpp:137）——说明作者知道这个坑，
但只修了两处。建议：叶子用"构造期 preferred 尺寸"做自然尺寸，`arrange` 尺寸单独存
（与 P0-1 的 `set_geometry` 一起做，一个入口解决两份几何）。

### P1-7 stretch 完全绕过 clamp，aspect 被 clamp 破坏（第 1 版遗漏）

`measure_child` 的顺序是 `pct → measure → aspect → clamp`，而 `arrange` 的 stretch：

```cpp
// vbox.cpp:194-196（Hbox 的 stretch_y 同理，hbox.cpp:182-184）
if (a.stretch_x && !pct_x) { item.size.x = available_w; ... }   // 没有 clamp_size
```

三个顺序缺陷：

1. **clamp 破坏 aspect**：先算宽高比再 clamp，任一轴被 min/max 截断后比例就不成立了；
2. **stretch 跳过 clamp**：交叉轴 stretch 直接赋值，可超过 `max_size`、也可破 `aspect_ratio`；
3. **stretch 跳过 fixed_size**：`fixed_size()` 声明"忽略 constraints"（P1-10），但 stretch 只检查
   `pct_x/pct_y`，不检查 fixed_size，于是"固定尺寸"控件照样被拉满。

建议顺序：`resolve spec(pct/flex/stretch) → measure → aspect → clamp`（aspect 与 clamp 一起求解），
stretch 结果再 clamp 一次，并让 fixed_size 在 stretch 前短路。

### P1-8 `set_visible(false)` 不影响流式布局：隐藏项仍占位

```
[9] vbox h: visible=40.0 hidden=40.0 ; b bounds y=20.0 h=20.0 visible=0
```

`Vbox/Hbox/Grid/Wrap` 的 measure/arrange 只跳过 `absolute()`，**不跳过不可见子项**
（vbox.cpp:70/125、hbox.cpp:70/118、grid.cpp:190、wrap.cpp:66）。而 `set_visible()` 会
`mark_layout_dirty()`（widget.hpp:129）——"可见性变化会触发重排，却不改变重排结果"。
目前只能 `clear_children()` 重建或包一层容器。

建议引入三态 `display`：`Flow`（参与流式布局）/ `Positioned`（absolute：不占位但仍 arrange）/
`Hidden`（完全不参与）。注意与 `TabView` 的联动：它现在用 `set_visible` 做页切换，
`measure` 又取所有页的 max（tab_view.hpp:140-144）→ 必须**先**让 TabView 只测当前页，再改可见性语义。

### P1-9 `Splitter` 完全绕过 `measure`，并用 `clips_children()` 掩盖后果

```
[6] splitter children measures: left=0 right=0
```

`Splitter::arrange()` 直接 `children_[0]->arrange({slot...})`（splitter.hpp:87-111），从不测量子项；
`measure()` 返回自身 `preferred_*`（splitter.hpp:81-85）；`clips_children() = true`（splitter.hpp:34）
把溢出裁掉而不是暴露。后果：Splitter 子树里的控件拿到"被分配的尺寸"而非"协商出的尺寸"，
`Table` / `FileBrowser` / `Section` 在 Splitter 里的行为与别处不同。
接入 `measure` 时要注意：一旦不再 clip 掩盖，必须同时有 `overflow` 策略（§4.2），否则溢出会变成可见错位。

### P1-10 `fixed_size()` 是死契约

文档宣称「`fixed_size() = true` 表示忽略 `constraints`，尺寸由 min/max 决定」，
`Table` / `Window` / `FileBrowser` 各有 override，两个测试还断言了它，但布局代码里 **0 个消费者**：

```
$ grep -rn "fixed_size()" src/ test/ | grep -v "override\|virtual bool fixed_size"
test/test_ui_window.cpp:367      assert(win->fixed_size());
test/test_ui_file_browser.cpp:145 assert(fixed.fixed_size());
test/test_ui_file_browser.cpp:152 assert(!flex.fixed_size());
```

真正的行为来自各控件自己的 `measure()`（`Table::measure` 返回 `clamp_size(min_size())`）。
注意 `Window::arrange` 已经自己忽略 `slot.size`（固定尺寸语义在那里）→ 让容器消费 `fixed_size`
时必须统一"谁说了算"，否则同一个 Window 在两套规则下行为不同（P1-7 第 3 点）。

### P1-11 布局契约测试**不可能失败**

`test/test_ui_layout_contract.cpp` 的 `check()` 失败只打印 `[KNOWN]`，`main()` 恒 `return 0`：

```cpp
void check(bool ok, const char* name, const char* detail) {
    if (ok) { ++g_passed; ... } else { ++g_known; printf("[KNOWN] %s -- %s\n", ...); }
}
std::printf("layout contract: %d passed, %d known deviations\n", g_passed, g_known);
return 0;                                  // ← 永远成功
```

当前输出 `7 passed, 0 known deviations`，任何回退都不会让 ctest 变红，安全网价值等于 0。
修法：`return g_known == 0 ? 0 : 1;`，并把本文件 P0-1/P0-2/P0-3/P1-4 的探针断言搬进去。

### P1-12 `mark_layout_dirty` 没有早退，而文档已经承诺了早退（第 1 版遗漏）

```cpp
// widget.hpp:330-335 —— 每次都走满整条祖先链
void mark_layout_dirty()
{
    layout_dirty_ = true;
    invalidate_measure();
    if (parent_) parent_->mark_layout_dirty();
}
```

而 `docs/ui_architecture.md:121` 写的是「`invalidate_measure()` 会沿 `parent` 链向上传播；
**已失效则不再重复向上**」——文档与实现不符。

三个连带问题：

1. **不能简单写 `if (layout_dirty_) return;`**：`layout_dirty_` 只在 root 被清
   （`UISystem::tick` / `main.cpp` 的 `clear_layout_dirty()`），子树标志一旦置 true 永不复位
   → 早退会**永久关闭**该子树的失效传播（窗口移动/缩放不再重排）。
   早退的判据必须换成"测量已失效"（`measure_valid_`）或新增 `propagated_` 标志，并在 layout 末尾统一清。
2. `TabView::invalidate_measure` 会递归**所有**子项（tab_view.hpp:126-129）→ 单次传播成本是
   O(子树) × O(深度)。
3. 布局期间每个叶子的 `set_size` 都会触发一次完整冒泡（配合 P1-4，这是"缓存永不命中"的原因）。

### P1-13 "无界"有三种写法，且语义不互通（第 1 版列在 §4.7，此处升级）

| 写法 | 使用位置 | 被谁认 |
|---|---|---|
| `1.0e8f` / `kUnbounded` | widget.hpp:257、grid.cpp:11、wrap.cpp:11、label.hpp:100、scroll_panel.hpp:46 | `measure_child` 只认这一种 |
| `1.0e9f` | scroll_panel.hpp:49、scroll_view.cpp:23-32 | 无（`>= 1e8` 恰好也命中） |
| `-1.0f` | section.hpp:75（`content_->measure({w, -1.0f})`）、各容器 `cached_constraints_{-1,-1}` | **无**：`measure_child` 判定 `>= 1e8` 才是无界，`-1` 会被当成"可用高度 = -1" |

具体后果：`Section` 给内容传 `-1` → `pct_y` 子项得到 `-1 × pct` → 被 clamp 成 **0 高**。
建议统一为 `kUnbounded` + `is_bounded(v)`，并让 `-1` 走同一支（或直接断言禁止）。

## 4. 结构性缺陷（短期不必修，但会持续制造 bug）

1. **四套流式实现各写一遍**：margin / spacing / align / pct / absolute / main_align 在
   `Vbox`、`Hbox`、`Grid`、`Wrap` 里各一份（约 4×150 行）。已可见的漂移：
   - `Wrap` 忽略 `a.x`（wrap.cpp:197「Wrap 不按 a.x 拉伸/偏移子项」）；
   - `Hbox::measure` **没有** `Vbox` 的 flex 主轴特例（vbox.cpp:83-85 对 flex 子项取 `min_size().y`，
     hbox.cpp:80 直接把 `cs.x` 计入 total）→ 同一个 flex 子项在两种容器里"自然尺寸"定义不同；
   - `Grid` 的 unbounded 分支另写一套列宽解析（grid.cpp:161-196）。
   抽一个轴向参数化的 `LinearLayout` 可消掉 4 份 `resolve_align`、4 份绝对子项摆放、4 份 extra 分配。
2. **无 flex-shrink、无 overflow 策略**：`extra <= 0` 时四个容器都不收缩也不报告，溢出交给祖先的
   `clips_children()` 静默裁掉（`Panel`/`Window`/`ScrollView`/`Splitter`）。缺 `overflow`
   声明（clip / scroll / shrink）与"内容超出"查询，`Splitter` 正是靠 clip 掩盖 P1-9。
3. **`Align` 的 x/y 语义随主轴漂移，且无基线对齐**：`Align.x` 在 `Vbox` 是交叉轴、在 `Hbox` 是主轴
   （被忽略）；同一常量（如 `center_left()`）在不同容器含义不同；没有 per-child 主轴对齐
   （justify-self）；Hbox 里 Label(16px) 与 Button(30px) 用 `a.y = 0.5` 做几何居中，不是文本基线
   对齐，混排字号时上下错位。CO-7 里 Hbox 行必须显式 `set_cross_align(center_left())` 是这层的副作用。
4. **两套坐标系 + root 是自由画布**：`UIRoot::layout_child` 用 `local_.pos`（`child.x()/y()`），
   `Vbox::arrange` 用 `absolute_pos_` + 内容区原点；`Window` 必须同时维护两者（window.hpp:41）。
   所以**顶层布局只能靠调用方手写**：`Editor::layout()` 里 7 处 `place(...)` + resize 回调
   （`tick` 里比较 `last_w_/last_h_`）重新摆菜单/工具栏/分割器/状态栏。缺一个"root 可选 Fill/Flow"
   模式（升级清单第 8 条），也缺顶层 margin/padding 的统一表达。
5. **裸容器不响应主题度量，且度量散落硬编码**：`Vbox/Hbox/Grid/Wrap` 没有 `set_context` 覆写，
   默认 `set_default_padding(4)`（vbox.cpp:13/20、hbox.cpp:13/20）与 `spacing_ = 4`（vbox.hpp:33、
   hbox.hpp:33、grid.hpp:67-68、wrap.hpp:70-71）——而 `Panel`/`TabView` 会跟随 `theme.padding/spacing`。
   字面量同样分散：`DialogHost` 的 `margin = 24 / max(120, …) / clamp(120|80)`
   （dialog.hpp:184-189）、`Window` 的 `160 / kDefaultTitleHeight+48 / keep_visible 48`
   （window.hpp:39、…）、`Splitter` 的 handle 尺寸等。升级清单第 9 条要做的就是把这些收进
   `Theme` 或 `LayoutMetrics`；做的时候必须复用 CO-7 的 `padding_override_` 语义，
   否则会退回"主题重刷冲掉显式 0"的老问题。
6. **布局 API 噪音**：`Widget` 上与布局相关的 setter **17 个**（含几何入口 `set_pos/set_size`），加上容器自己的
   **18 个**（`set_spacing` / `set_main_align` / `set_cross_align` / `set_cell_align` /
   `set_column_widths` / `set_row_align` / `set_content_inset` / `set_tab_gap` / `set_page_fill` …）。
   同一个"我要填满/居中/占 50%"要跨 2–3 个 setter 表达，且互相覆盖顺序不明确（P1-7）。
   升级清单第 12 条的 `LayoutSpec` 能把规格收敛成一份数据，但要在 P0/P1 规则定稿之后再抽，
   否则 spec 会跟着改两轮。
7. **`measure` 与 `arrange` 不是纯函数对**：`arrange` 内部 `set_size` → `mark_layout_dirty`，
   布局过程本身制造脏状态；正确性依赖"脏标记在上层被 clear"以及"叶子 set_size 顺手清掉祖先缓存"
   （P1-4）。任何在布局之外调用 `container->layout()` 的代码都会用陈旧矩形重排（P0-1）。

## 5. 与 ui #1 / #2 的关系

- ui #1 只把布局列为「四个核心契约里的 measure / fixed_size」，未实测；本次证实 `fixed_size()`
  无消费者（P1-10）、「measure ≤ constraints」被违反 1 处 + 4 处用返回约束模拟 fill（P0-3）。
- ui #2 的「主题可变性边界不闭合」在布局侧有同构问题（P1-4）；两者共用一个修法：
  **把主题版本号并进所有派生缓存**。
- ui #2 **没有覆盖**"裸容器不响应主题度量"与"布局字面量散落"（它只写了 Panel/TabView 注入与
  两套密度机制）——本版补进 §4.5。
- CO-7（padding 显式优先）处理的是"覆盖语义"；P0-1/P1-6 是同一类问题的另一面（几何写入 vs 脏标记耦合）。

## 附录 A：探针 A 节选（`/tmp/layout_probe.cpp`）

```cpp
struct Counted : Widget {                 // 统计 measure 调用次数
    int measures = 0;
    glm::vec2 natural{10.0f, 10.0f};
    glm::vec2 measure(glm::vec2) override { ++measures; return natural; }
    void arrange(Rect slot) override { global_ = slot; set_pos(slot.pos); set_size(slot.size); }
    void append_to(xel::graphics::DrawList&) const override {}
};

// [1][2] 每轮布局的测量次数
Vbox box(0, 0, 300, 200); box.set_padding(0); add(box); add(box);
box.measure({300, 200});  box.arrange({{0,0},{300,200}});        // a=1 → a=2

// [3] Wrap 违反 measure <= constraints
Wrap wrap(0, 0, 200, 100); add(wrap, {300, 20});
wrap.measure({200, 100});                                        // → 300

// [4] 两个 pct_y=1 的子项
Vbox v(0, 0, 400, 300); a->set_size_percent({0,1}); b->set_size_percent({0,1});
v.measure({400, 300}); v.arrange({{0,0},{400,300}});              // measure 600；b 底边 = 600

// [5] 三个 pct_x=0.5 的子项
Hbox row(0, 0, 400, 100); ... set_size_percent({0.5f, 0});        // measure.x = 600

// [6] Splitter 不测子项
splitter.set_panes(left, right); splitter.arrange({{0,0},{400,300}});   // measures = 0

// [7b] 主题切换后 measure 缓存仍是旧值（容器套容器）
root->add(outer{Vbox> inner{Vbox> button}}); root->layout();
Theme t = root->ui_theme(); t.control_height = 60; root->set_theme(t);
outer->measure({400, 300});                                      // 仍 30（缓存命中）

// [7c] 同一场景走 UISystem::tick：下一次 tick 自愈（副作用失效）
system->set_theme(t); system->tick();                            // outer.h 30 → 60

// [8] arrange 不写 local_；layout() 用陈旧矩形
box.arrange({{50,60},{400,300}});  box.layout();                  // child.w 400 → 100

// [9] 隐藏仍占位
b->set_visible(false); box.measure({200,300});                    // 高度不变
```
